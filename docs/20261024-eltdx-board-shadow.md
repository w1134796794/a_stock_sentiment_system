# eltdx 3.3.0 板块扩展

## 范围与授权

本轮增加通达信板块自身行情的独立影子采集、成员差异对照、可靠归档和只读诊断。
不替代 Tushare，不改变正式买点的模式、覆盖率、量能、时序和新鲜度门槛，也不发送预警或通知。

[eltdx 3.3.0 发布说明](https://pypi.org/project/eltdx/3.3.0/)限制生产、商业和付费服务用途。
本功能默认关闭，按本地研究工具实现；正式部署前必须另行确认授权及数据源使用条款。

## 盘前准备

在已有盘前证据、真实日历和个股采集名单准备正常的基础上，当天 09:25 前执行：

```sh
python scripts/prepare_realtime_collection.py --tdx-boards
```

该命令会请求 `helpers.board_quotes(category="全部")` 准备资料和定义。
它会拉取整个分类，而非仅本项目板块，因此只在盘前使用，不放进盘中轮询。
对名称完全一致的候选板块，以及显式指定的代码，请求 `helpers.board_member_quotes()` 比较成员。
其他名称保持未映射，不自动猜测同义词。

可选的 UTF-8 JSON 对照文件格式为 `{ "同花顺板块名称": "sh880xxx" }`，值必须是源端真实存在的带市场代码。
使用 `--board-mappings <文件路径>` 与 `--tdx-boards` 一起传入。
显式对照也只是研究候选，不视为正式确认授权或同体系证明。

冻结结果保存到 `WEB_DATA_DIR/collection_plans/tdx_boards/YYYYMMDD.json`，绑定原个股采集计划哈希。
保留交集数、双方成员数、Jaccard、双方独有成员及 SDK 排除理由。
SDK 的“当前证券名单缺失”不作为退市证据；原同花顺分母不受该映射修改。
同日结果不可替换，过时日期、盘中补建、准备过程跨过 09:25 均拒绝发布。
SDK `prepared_date` 仅记录资料准备日期，不证明每个资源下载成功或全部最新。

## 盘中通道

本地研究环境设置以下变量后启动现有独立采集器：

```text
ELTDX_BOARD_SHADOW_ENABLED=true
ELTDX_BOARD_POLL_SECONDS=10
ELTDX_BOARD_STALE_SECONDS=20
```

默认间隔 10 秒、最短 5 秒。这是调度目标，不是源端实时性承诺。
采集器中的独立线程使用单独 Provider，只请求冻结的带市场板块代码，每批最多 80 个。
盘中不调用板块资料准备、成员发现或同花顺接口；无当天匹配计划时只记录缺失。
前一轮未完成不堆积任务，午休和交易时段外不请求；租约丢失或跨日后不发布结果。
个股 3 秒通道、成分股通道及现有分钟兜底不改变配置或正式门槛。

板块身份保留 `sh880xxx` 等完整代码，不推断为个股 `.BJ` 或写入个股快照键。
每条报价先写现有 SQLite 可靠增量队列，再更新 Redis/本地热窗口。
沿用独立 archiver 按日落库，不等热窗口到期才保存；热序列保留最近 180 秒。
失败保留上一批数据，但诊断仍按原接收时间检查过期，不能用健康更新时间续期。
健康键为 `realtime:tdx-board:health`，包含逐批耗时、缺失代码、拒收数、当前计划和错误分类。
父采集器健康信息中同时提供 `tdx_board_shadow`。

## 只读诊断

```sh
python scripts/diagnose_board_shadow.py
python scripts/diagnose_board_shadow.py --market-date YYYYMMDD --archive
```

当前诊断比较 TDX 指数与冻结 THS 成分股宽度，展示实际接收时间、年龄、价格相对昨收/真实开盘的变化、
实际观测跨度、最大采样间隔与覆盖率。成员缺失不缩小分母；过期、未来和异日数据不计有效成员。
两条采集通道尚未完成同组同刻和 3 分钟锚点对齐，因此显式标记为独立最新观测，不能当成共振成立。
`continuity_ok` 仅描述当前已观测窗口的间隔，窗口长度单独输出，不代表已经覆盖完整 3 分钟。
协议时间字段仍是不透明原值，`fresh_receipt` 只表示接收新鲜度，`exchange_timestamp_verified=false`。

归档模式合并按日库与待归档队列，按事件 ID 去重；只读打开已有文件，不创建或补取数据。
按实际快照聚合采样 OHLC，09:30:50 和 09:31:00 均归入收于 09:31 的分钟。
缺失分钟不补齐，当前分钟标记未闭合；采样 OHLC 不冒充交易所完整分钟 K 线。
这些分钟不加入正式买点判定，正式分钟回放仍消费原有证据。

## 影子诊断回放与逐点对账

当天诊断回放页面新增独立的“板块影子回放”入口，即使个股候选缺失也可运行。
只读 API 为 `GET /api/intraday-replay/board-shadow/YYYYMMDD?until=HH:MM:SS`。
它只读取已经冻结的本地计划、按日归档与待归档队列，不补取、不发布事件、不写账户或通知。
普通分钟回放报告也会包含独立的 `board_shadow` 附录，但其结果不影响正式买点或原报告完整性。
对照重跑使用报告中冻结的 `board_shadow_inputs`，不会读取后来新增的快照或当前热缓存。

```sh
python scripts/replay_board_shadow.py --market-date YYYYMMDD --until 10:00:00
python scripts/replay_board_shadow.py --fixture tests/fixtures/board_shadow_replay.json
```

固定样本明确标记 `synthetic=true`，仅检查无未来数据、实际样本数和过期边界，不能作为实盘验证。
合成快照禁止写入真实板块采集存储。无计划、无快照、异日、来源不符、证据损坏分别标记缺失/异常。
回放同时按接收时间和采集时判定完成时间裁剪，不把较晚完成的判定提前到行情接收时点。

新增真实采集记录包含 `capture_evaluated_at`、`capture_policy`、`assessment_version` 和 `assessment_at_capture`。
实时与回放共用纯判定函数。回放逐点展示一致、不一致及具体字段差异；旧记录没有原判定时标记无法对账，
绝不把重算出的判定反写成历史实盘记录。全点一致也不代表正式买点或推送已验证。
现有历史 THS 宽度仍按原证据检查，不能从当前报价补造过去同刻的参与面。

部署流程在重启前执行 SDK 离线检查与固定合成样本验证；成功推送不等于该部署流程成功。
下一实际交易日采集完成后，使用当天归档执行只读回放，检查逐点对账、采样空窗和缺证据情况。
2026-10-24 的真实日历核验结果为下一交易日 20261026，已安排该日 16:10 在本线程跟进验收。
若服务器仅允许免密 `systemctl status a-stock`，不能给该 sudo 命令额外添加参数。
部署状态查询改为普通权限；重启使用 `sudo -n`，缺权限快速失败，不等待交互密码。
已安装行情进程组时，部署账号还需由 root 单独授予精确的
`/usr/bin/systemctl restart a-stock-market.target` 免密权限，不应扩大到任意 systemctl 或任意 sudo 命令。
