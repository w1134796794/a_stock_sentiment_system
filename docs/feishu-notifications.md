# 飞书群消息推送

支持自定义群机器人文本消息，复用现有正式买点、持仓退出及任务通知入口。
不创建飞书应用，不接收回调，不改变策略确认、模拟交易或账户。

## 配置

在飞书目标群添加自定义机器人，将地址和可选签名密钥写入服务器现有 `.env`：

```dotenv
FEISHU_WEBHOOK_URL=https://open.feishu.cn/open-apis/bot/v2/hook/REPLACE_ME
FEISHU_SIGN_SECRET=
```

建议开启签名校验，并填写对应密钥；若启用关键词或IP白名单，还需保证消息包含关键词、
服务器出站IP在白名单。系统通知标题不同，关键词必须适合所有需要接收的消息。
不要将真实Webhook、密钥提交Git或粘贴到日志中。服务器需要能够出站访问飞书HTTPS，
且系统时间需准确；无需开放入站端口。

更新环境后，按实际安装方式重启发送通知的进程：通常包括Web服务、独立策略服务和
持仓监控所在的执行服务。示例（先确认这些unit确实已安装）：

```bash
sudo systemctl restart a-stock a-stock-strategy a-stock-execution
```

配置页“消息推送”会显示飞书配置状态。“发送测试”会发送到所有已配置渠道，
不是仅飞书；请在预期接收群准备就绪后由管理员手动测试。

## 发送语义

- 未配置地址时不启用飞书，保留现有微信/钉钉行为。
- HTTP成功且飞书业务码明确为0才记录成功；非零、缺业务码、错误JSON和网络异常均失败。
- 同一事件每个目标地址分别去重、分别记录重试；飞书失败不重新发送已成功的微信消息。
- 盘中信号沿用现有通知outbox；其他调用沿用各自已有重试机制，不新增独立调度器。
- 超时存在“对方已收到、响应丢失”的可能，重试不能保证第三方端严格只收到一次。
- 返回记录只保留状态、业务码及脱敏错误类型，不记录飞书URL、密钥、签名或原始响应。
- 本功能未增加消息卡片、私聊、交互按钮或独立批量限流器；集中大量推送仍需关注平台频控。

协议参考：[飞书官方自定义机器人指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot?lang=zh-CN)。
