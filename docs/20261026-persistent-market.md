# 统一持久化盘中行情

## 数据与读取

秒级个股快照、个股分钟K线版本、板块成分股分钟价格观测统一写入
`WEB_DATA_DIR/market_archive/ingestion.sqlite3`，异步转入同目录按日
`market_YYYYMMDD.sqlite3`。已有通达信板块指数快照与竞价也使用该入口。
板块成分分钟是实际采样价格点，不冒充OHLC或逐笔成交。

`PersistentMarketReader` 查询待归档与已归档记录，以事件ID去重。
读取、转档与跨日清理使用同一个短文件锁，避免转档中漏读。连接只读打开；
读取不创建行情数据库，不调用任何行情API。需要Web、策略、采集与归档进程访问
同一个本机数据目录。SQLite WAL库不直接通过网络文件系统跨机共享；跨机器部署
需要先提供行情读取服务，再切换到该路径。

新事件保存 `write_seq`、`persisted_ts`、`received_ts`、`event_ts`。
策略每只股票的一轮判定固定asof和写入序号上界，排除该轮开始后持久化的记录。
同一批候选逐股重新取得边界，避免串行计算较慢时，后面的股票沿用整批开始时的旧行情。
原始行情时间及接收时间保持不变；迟到/补取不能伪造当时可见性。
SQLite保留旧表和旧行；旧记录无法证明持久化时间时标为
`legacy_visibility_unknown`，不作为连续快照质量合格的证明。
分钟版本按内容去重，重复轮询不再反复写整天分钟序列；发生修订时追加新版本。

实时策略的报价、连续快照、分钟、竞价和可选板块趋势通过持久化读取。
Redis继续提供心跳、任务租约、更新通知、页面缓存；180秒窗口不再限制持久化查询。
同股一轮固定读取边界不会降低实际执行时的新鲜度门槛，计算过慢仍会被拦截。

## 板块时间区间

板块宽度检查按实际评估分钟及前三分钟懒加载；例如15:00诊断10:00，
读取10:00和09:57观测。没有观测的分钟保持缺失，不前向填充，不降低60%覆盖门槛。
已归档快照回放也合并逐分钟版本，并按接收/持久化两者较晚的可见时间推进。

## Debug

逐股结果增加 `market_data_view` 和 `market_data_reads`，记录评估时点、序号上界、
请求区间、实际返回数量、最大快照间隔、缺失股票、读取错误、部分事件ID及耗时。
这些信息进入统一debug及策略观察留档。读取故障与真实空结果分开显示。
原始行会跨日删除，因此debug保留判定值、阈值、覆盖率与快照样本，不能保证次日
还能完整重算前一天。已另存的回放输入、冻结策略输入和debug不会被清理。
`check_market_readiness.py`的线上输入检查也读取持久化行情，Redis只用于进程健康，
报告标注 `input_storage=durable_spool_and_archive`。旧的 `hot_*` 检查键名保留兼容。

```bash
cd /opt/a_stock_sentiment_system
.venv/bin/python scripts/read_persistent_market.py --date 20261027 --codes 300369 --start 09:30:00 --end 10:00:00
.venv/bin/python scripts/read_persistent_market.py --date 20261027 --codes 300369 --kind minutes --asof 10:00:00
.venv/bin/python scripts/read_persistent_market.py --date 20261027 --codes 000001,000002 --kind sector_minutes --start 09:57:00 --end 10:00:00
```

## 跨日清理

采集器取得唯一任务租约后，在新交易日首次采集之前执行清理。
先等待本进程旧异步任务结束；清理与所有新旧归档/写入互斥。
只删除严格早于当前日期的按日原始行情数据库、待归档事件、旧证据游标、
`CACHE_DIR/stock/sector_quote_minutes`旧日库，以及明确白名单中的旧实时Redis键。
旧SQLite先检查WAL能否完整checkpoint；仍被占用则停止清理，保留文件。
不使用 `FLUSHDB`，不删除任何租约、冻结计划、策略结果或通知队列。

完成后写 `market_archive/active_day.json`，同日重启不清空、不重复清理。
晚到的旧日写入被拒绝，不能重新生成已退役的数据库。
`stock/tick`历史研究分钟CSV、盘后数据、冻结计划、研究回放、账户和debug都不在清理范围。
现有ingestion库删除旧事件后会复用空闲页，不在采集启动时执行高成本VACUUM。

## 部署与验收

此变更需同时更新采集器、归档器、策略和Web的代码；避免旧采集器继续写旧格式。
在停用旧采集/归档写入后统一切换版本，再启动各独立服务。首次启动会按上述规则
删除旧日期原始实时行情；如需保留旧日完整回放，应在切换前另存回放输入。
不删除或重建当日冻结配置，开盘窗口仍按冻结的1/3/5或旧版参数解释。

验证清理报告、当前日数据保留、同日重启续存，以及debug中的持久化视图和目标分钟。
本地测试通过不代表已部署或已经读取生产数据。
