# 分钟缓存修复与策略配置同步

## 分钟证据

历史分钟数据必须覆盖完整连续交易时段。校验支持09:30或09:31起始的分钟标记口径，午休不算缺口；检查日期、分钟重复、交易分钟缺失，以及价格和成交量的有效性。不补造缺失分钟，不用收盘快照冒充历史分时。

完整缓存继续复用。缺失、半天、日期不符或损坏的缓存会在允许历史取数的调用中自动向现有数据源补取；不完整的远端结果不会覆盖原缓存。缓存写入采用临时文件原子替换。`get_stock_tick(..., force_refresh=True, require_full_day=True)`可用于显式强制刷新。

当日盘中按已收盘分钟检查，不要求尚未发生的下午数据。历史回放始终要求全天完整数据。缓存完整不等于接口报价绝对准确，也不等于具备集合竞价、板块分时或历史同分钟量能等其他证据。

模拟交易页的“回放缺失证据”显示日期、股票、证据项与具体原因。接力回放保存阻塞明细，重启后仍可查询。历史重建预取失败时不会继续启动回测，也不会把缺证据的重建结果导入账户。

Linux服务器的行情节点限制不变：服务端模式不直接连接eltdx。若服务器缺少历史分钟，需要由有权限连接行情源的采集节点获取并同步缓存；页面会列出源不可用或禁止补取的原因。不要为补历史数据开放服务器盘中直连行情节点。

## 策略配置同步

1. 在来源环境打开“策略组合”，点击“导出配置”。导出的是当前生效配置，不仅是源码默认值。
2. 在目标环境更新相同代码，打开“策略组合”，点击“导入比较”并选择导出的JSON。
3. 核对当前版本、导入后版本，以及截止时间、市场阶段、入场模式、因子过滤等具体差异。
4. 点击“确认导入”。如果比较之后目标配置又发生变化，导入会被拒绝，必须重新比较。
5. 旧配置备份在运行策略配置文件旁，文件名含`backup-`。重新执行对应日期的选股和快照任务，已有候选不会因导入自动重算。

导入同步策略和基础方案快照，避免两端从不同默认基础方案继承参数。保留目标环境独有策略，并在预览中显示；因此存在额外策略时，两端整体版本可能仍不同。不会覆盖模拟账户、手工成交、通知密钥、风控配置、因子数据和模型文件，也不会主动推送到远端服务器。

配置相同并不保证候选相同。还需要相同代码、因子/历史数据、模型权重和选股日期。不同环境的非策略风控设置需另行核对。

接口：

- `GET /api/strategies/config/export`：下载配置包。
- `POST /api/strategies/config/compare`：请求体`{"bundle": 导出的配置包}`，只比较不写入。
- `POST /api/strategies/config/import`：请求体`{"bundle": 导出的配置包, "expected_version": 比较返回的current_version}`。

沿用策略管理权限。导入后接力账户仍检查配置版本，不会修改旧检查点来绕过版本保护；跨版本验证使用独立历史重建账户。
