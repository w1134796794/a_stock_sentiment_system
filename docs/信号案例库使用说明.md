# 信号案例库：Phase 0—2 使用说明

更新日期：2026-10-07。

本次完成历史统计口径修正、信号时点冻结、独立交易样本及结果标签。
Phase 3—4 已补上独立的相似匹配和校准验证服务，见《相似评估与滚动验证使用说明.md》。
还没有接入工作台相似案例视图、实时回调展示或概率驱动换股。
不会重置、覆盖现有模拟账户，也不会发送历史补建的买卖通知。

## 1. 自动运行

沿用现有盘后流水线的时间安排。取数、因子、选股和页面快照完成后，
`ETLDailyPipeline.run_screening()` 会调用信号案例增量任务：

1. 将盘中 SQLite 中首次确认的案例归档到因子 DuckDB。
2. 读取上一交易日冻结的生产决策池，检查当天的分钟确认。
3. 对可成交的确认信号建立独立标准化交易，不受当前账户现金、持仓数和板块仓位影响。
4. 从每个案例最后完成日期之后继续计算退出和结果。
5. 写出 `WEB_DATA_DIR/signal_cases/coverage_YYYYMMDD.json`。

自动任务仅使用本地分钟、竞价缓存，不在这个附加阶段联网补历史。
案例任务异常会写入流水线警告，不撤销已生成的选股或页面快照。
这不是新的定时器；部署代码并重启原服务后生效。

## 2. 初始化或补建历史

以下日期指行情日，系统会读取对应上一交易日的候选决策池：

```bash
python scripts/build_signal_cases.py --start 20260801 --end 20260924 --report output/signal_case_coverage.json
```

默认只读缓存，不承诺旧日期的分钟数据一定可以获得。
需要尝试联网补齐时显式开启：

```bash
python scripts/build_signal_cases.py --start 20260801 --end 20260924 --fetch-missing --report output/signal_case_coverage.json
```

仍使用现有 eltdx 历史分钟接口。完整缓存不会重复抓取；不足一个完整交易日的缓存会在允许补取时尝试修复。
必须有真实交易日历、冻结的生产决策池、所需个股及板块成分分钟证据、日线等基础数据。
脚本只按案例所需股票读取，不重新计算全市场因子。

可重复运行同一日期区间：完成的确认尝试跳过，缺证据的尝试重试；
已有交易案例从下一未完成日期继续，成熟标签不可覆盖。
案例初始化和每个交易日的标签/接力状态在事务中保存。

只查看覆盖情况：

```bash
python scripts/build_signal_cases.py --coverage-only
```

`--db` 可指定独立研究 DuckDB，`--web-data-dir` 可指定候选数据目录。
历史输入缺失、案例阻断或初始化阻断时，脚本返回退出码2；
这不代表整个区间所有案例都失败，应查看报告中的具体状态。
建议在盘后单写进程中执行，避免与因子任务同时写同一个 DuckDB。

## 3. 数据位置与状态

现有持仓 SQLite 增加 `signal_case_staging`，首次有效确认写入后不覆盖。
现有因子 DuckDB 增加：

| 表 | 用途 |
|---|---|
| `signal_cases` | 不可变信号、身份、版本、首次触发时间和紧凑特征 |
| `signal_case_attempts` | 候选确认尝试、策略否决、缺证据和不可成交原因 |
| `signal_case_progress` | 独立交易的引擎状态、最后完成日期、成本与退出版本 |
| `signal_case_outcomes` | 各结果标签及独立的成熟/可获得时间 |

状态解释：

- `strategy_veto`：冻结决策池本来就不允许执行，不能算作买入失败。
- `no_opportunity`：在已有证据下没有形成有效确认。
- `blocked`：缺分钟、板块、日线或其他必要证据；不当成没有机会。
- `initialization_blocked`：盘中案例已留痕，但缺冻结配置或初始化证据。
- `unfilled`：确认过走势，但没有符合执行约束的成交窗口。
- `pending`：已建立独立交易，尚未完整平仓或标签尚未全部成熟。
- `complete`：交易完整平仓，且D+1/3/5等规定标签计算完成。
- `mature`：某一个结果标签已经完成，并记录何时可以查询。

手工成交仍属于原账户流水，不自动伪装成有策略时点特征的历史案例。
五个生产策略沿用冻结决策池的执行配置；龙头观察从实际盘中确认事件归档。
没有冻结的历史龙头观察记录时，不凭今天重算的龙头身份补造历史实时事件。

## 4. 时间与成交口径

`confirm_minute_at` 是原引擎的分钟标签；`minute_closed_at` 是该分钟结束边界。
实时案例的 `confirm_at` 至少不早于分钟结束、报价接收及板块观测时间。
冻结特征只使用确认分钟及之前的分钟，不使用随后最高价、全天成交量或收盘结果。
报价来源/接收时间、板块观测时间和实际记录时间分别保留。

实时策略/成本/退出参数在确认时冻结。历史重建使用本次固定参数版本，
来源标为 `reconstructed`，默认不作为已经证明时点正确的历史预测。
未知特征保留null，质量字段列出缺失项，不填0或50分。

独立交易复用分钟入场和退出判断，使用合法交易单位：普通A股100股，科创板200股。
费用按冻结佣金和税费假设计算；滑点已进入成交价，不重复扣除。
卖出按信号后可观测的成交窗口估计，不保证成交在保护价。
当日买入不允许当日卖出；跌停锁死时保留退出意图，等待后续可成交窗口。
缺日线、缺完整分钟或无法核对的除权现金流会阻断对应案例。

eltdx 历史分时可能只提供分钟价格点，不是真实OHLC或逐笔委托队列。
此类结果标记为 `minute_point_next_observation`；完整分钟OHLC估计另行标记。
浮盈/浮亏只从成交后计算，退出后的行情不进入交易段MFE/MAE。
这些均为执行估计，不能声称与真实成交完全无误差。

## 5. 成熟标签与历史统计

标签包括完整平仓净收益、是否盈利、成交后MFE/MAE，以及D+1/3/5收盘收益。
部分卖出以完整交易段累计现金流、费用和剩余股数判断是否平仓。
未平仓不算亏损或成功；D+1/3/5收盘收益是未实现价格收益，不等于交易净收益。

每个标签分别保存 `label_end_at` 和 `available_at`。
实际补建时间不会倒填成当年的可获得时间；严格查询要求两者都早于查询时点。
查询研究重建结果需要显式选择研究口径，例如：

```python
repository.outcomes(case_id, as_of="2026-10-08T00:00:00", research=True)
```

原盘中历史概率现在标为“入场模式历史统计”，并返回未校准/样本不足状态。
统计需要完整买卖段、结果结束与可获得时间，以及明确策略、退出、成本版本。
重复回测不增加样本；版本不唯一时需要明确选择，不能无提示合并。
不满足条件的旧文件不会继续输出看似精确的成功率。

## 6. 当前边界

代码实现不等于历史数据已经补齐。本次没有自动全量联网回放或重置账户。
首次初始化应先看覆盖报告，再按缺失范围补数据。
相似统计和样本外校准服务已实现；工作台/微信展示属于Phase 5，目前不会改变原有交易规则。
