# ST过滤与退市分钟缺失处理

## 统一新入场限制

选股、决策池、龙头池、盘中确认、模拟自动买入、历史交易计划和板块参考样本，统一使用 `core/utils/stock_eligibility.py`。

- 记录名称为 ST、*ST、SST、S*ST，或明确 `is_st=true/1`：不进入新候选和龙头池。
- 记录名称明确处于退市整理状态：不进入新候选和龙头池。
- 无名称或状态未知：不凭股票代码猜测风险状态。
- 原始行情、市场统计和已存在持仓不会因过滤而被删除。手工成交仍保留。

## 历史时点约束

历史重建只使用对应候选日的成果和因子记录，不按今天的上市状态删除过去的股票。后来退市的股票，在历史上正常上市时仍可以进入样本，否则会产生幸存者偏差。

当前过滤依赖存量记录的名称和 ST 标记。如果旧分区曾用当前股票名称回填，它并不能保证严格的历史 ST 时点准确性。严格评估仍需补充历史名称变更和风险警示生效区间，并按日期关联；本次没有用今天的状态冒充历史状态。

## 分钟证据的三种角色

- 候选：严格重建时缺证据阻断；独立重建勾选跳过模式时，记录日期、股票和缺失项，跳过该日买入确认。
- 持仓：缺少必要退出分钟证据仍停止，不猜测止损或成交价。已有官方全天停牌证据时沿用既有停牌处理。
- 板块参考成分：单只缺分钟仅记录 `sector_peer` 警告，不在预取阶段直接阻断整个重建。确认时仍须满足原有板块观测门槛；整体证据不足依然按候选严格/跳过规则处理。

退市后行情接口可能不再提供历史分钟。过滤并不能恢复这类数据；历史上合规的非持仓候选可按跳过模式处理，持仓则必须补充可信历史分钟或保留阻断。

## 使用方式

更新代码并重启服务后，重新发起独立历史重建即可应用新过滤。旧候选页面成果需要重跑相应日期选股来刷新，原始行情无须为 ST 过滤而重取。

过滤逻辑纳入账户配置版本。已有默认账户检查点不自动换规则接力，应按原规则继续或使用独立账户重新研究，不能无提示混用新旧规则。本次修复不重置或重建任何模拟账户。
