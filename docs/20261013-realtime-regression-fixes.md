# 2026-10-13 盘中确认已知问题修复

## 范围与边界

本次修复针对本地代码中可复现的基础设施问题。尚未取得服务器运行版本及当天日志，不能断言服务器的唯一根因，也没有远程部署、发送真实通知或触发真实交易。

没有降低买点阈值，没有关闭健康门禁。个股行情 12 秒、板块观测 30 秒、板块覆盖率 60%、信号年龄 90 秒等限制保持不变。开盘前冻结证据不能在盘中补造，采集空窗中的历史分钟补齐不能当成实时买点补发。

## 已修复

1. Web 报价缓存从至少 15 秒改为最多 3 秒，并受行情过期阈值约束。每次读取重新计算源时间与接收时间的年龄，过期缓存立即重新读取 provider，不重写原接收时间来伪造新鲜行情。
2. 分钟上下文加载可能较慢，逐股确认前重新读取报价；响应使用同一份更新后的报价，减少开始加载时的报价在确认时已过期的问题。
3. 行情、板块观测、采集器心跳、快照判断及新生成的数据凭证使用上海时区。带 UTC 时区的接收时间正确转换，旧的无时区行情时间按上海时间解释；既有历史凭证没有被改写或回填时间。
4. 因子 runner 自身负责写成功清单，直接调用与流水线调用保持一致。默认因子 CLI 执行 market/lhb/signals/sector/stock 全部任务。部分重跑不能沿用之前完整成功清单，失败或中断保持非完整状态。
5. 取数开始前先原子写入 running 状态，完成后再写 done。因子及取数凭证使用临时文件、fsync、原子替换，避免读取半截 JSON 或重跑失败仍看到旧成功。Silver 原有必要数据要求没有改为强制所有可选增强接口成功。
6. 即使没有产生原始买点，也返回 execution_health，并按分钟输出基础设施阻断原因。API 的 ok 表示接口正常返回，不等于 execution_ready。逐股板块覆盖、报价新鲜度等检查仍另行执行。
7. 采集器输出协议版本及能力说明。健康检查要求真实租约、心跳和当日连续采集起点；缺字段或连续起点无效明确阻断，不为旧采集器伪造证明。与已有的连续采集空窗保护共同阻止迟到分钟冒充实时确认。

本次依赖当前工作区已有的数据库连接互斥、盘前不可变冻结包、同花顺真实成分股快照扩充以及 eltdx 局部缺股隔离修复。需要部署完整兼容版本，不能只同步 Web 文件。
