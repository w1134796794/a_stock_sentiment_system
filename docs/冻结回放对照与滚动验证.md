# 冻结回放对照与滚动验证

## 入口

策略评估页面选择 **冻结回放对照**，填写起止交易日和窗口，再点 **冻结并运行四组对照**。后台运行，页面显示当前组、日期和阶段进度；刷新后可恢复状态。已有冻结实验可点 **接力运行**，从各组最后完成日之后继续。

四组是独立研究账户，只存在研究目录和实验台账中。不重置、导入或修改模拟账户，不发送买卖通知，不修改生产配置或因子权重。

## 四组对照

| 组别 | 改变项 | 保持项 |
| --- | --- | --- |
| 原 34% 三仓 | 修复后生产计划与真实分钟撮合基准 | 原三仓账户约束、成本、退出、换仓规则 |
| 固定风险 | 仓位金额改为单笔账户风险 0.5% ÷ 含成本的保护距离 | 同候选、同确认、同退出及完全相同的仓位上限规则 |
| 持续确认 | 原分钟确认后，再观察两根连续完成的分钟：收盘不低于原确认价且位于 VWAP 上方；再检验板块同步，下一分钟有量且未封板才估算成交 | 固定风险组的候选、仓位和退出 |
| 候选前半组 | 每个候选日、每策略按冻结候选分数保留前 50%；并列以代码打破；至少保留一只 | 固定风险组的确认、仓位和退出 |

持续确认不倒选当日最佳价格：原确认失效、等待超时、分钟中断、缺少成交量或封板都不成交。它是对首次确认的预注册过滤实验，不会继续寻找当天更优的二次确认。候选前半组只比较既有候选中的选股收窄，不代表重建全市场的另一种选股模型。两者都没有因为原亏损样本临时调阈值。

固定风险组只替换金额算法；为保证纯变量对照，三仓数量和原账户覆盖策略仓位提示的约束语义保持一致。生产账户若要同时恢复市场仓位上限或题材集中度，需要另冻结实验，不能把效果归因于单独仓位算法。

## 冻结与证据

- 新生成修复后的生产决策计划，保留 T-1 计划。缺候选日快照、缺任一策略的产物、缺执行配置时拒绝冻结；不能把缺文件当作零候选。
- 将个股日线、已有分钟和可信竞价缓存、停复牌状态、历史板块样本映射复制到只读证据包；冻结阶段不连接远端分钟节点。
- 每只候选及参考样本从首次出现的前一交易日一直保存到区间末，避免后来持仓退出读取不同版本的行情。
- 成交进度模型必须具有区间之前训练完成的日期证明，否则冻结为空并标明原因，不把区间之后训练的模型用于过去信号。
- 参数、候选文件、证据数据库、配置、代码版本均有校验。任一变化需要创建新实验，不能接力旧合同。
- 当天日线不足不能完整估值；持仓缺分钟始终停止。严格模式下候选缺证据也停止；独立研究可选跳过缺证据候选，但结果仍标记不完整。
- 每日账户状态、候选跳过记录和覆盖分母原子保存。Windows/Linux 使用进程锁，防止同一实验被并发接力。

冻结并不证明过去已经产生这些配置或候选。历史回填始终是历史研究，不自动成为前瞻样本外表现。

## 滚动验证

默认训练 30 个交易日、隔离 5 日、验证 10 日。只展示完整验证窗口。每个窗口的训练选优目标预先固定为“训练区间净收益率 - 最大回撤率”，且只统计训练结束前已经平仓、在训练区间入场的交易用于样本门槛。

- 至少 20 笔训练平仓样本才参与选优；不足则“不选优 / 训练样本不足”。
- 验证期表现不能参与训练期选优。后续区间缺数据也不能倒过来改变早期窗口的训练选择。
- 验证期按策略与入场时市场阶段统计候选、确认、成交、平仓、含费损益和胜率。跨窗口未平仓或从更早窗口带入的交易不混入新验证入场队列。
- 账户收益和回撤保留四个独立连续账户的真实现金与持仓路径；不是将不同方案的好窗口拼接成一条可执行净值。训练选择仅是研究标记，不产生虚构的切换账户。
- 至少 3 个完整窗口且累计 30 笔验证期平仓样本，完整数据组才标为“历史对照”；仍不授权生产发布。少量样本只显示“证据不足”。

报告同时展示含费净收益、最大回撤、最差日、回撤持续天数、最大连续亏损、胜率、费用，以及检查点中的成交时间、仓位算法、MFE/MAE。研究目标是改善风险收益，不保证稳定盈利。

## 命令行

```powershell
.venv\Scripts\python.exe scripts/replay_research.py freeze --start 20260701 --end 20261009
.venv\Scripts\python.exe scripts/replay_research.py run 实验ID
.venv\Scripts\python.exe scripts/replay_research.py verify 实验ID
```

Linux 用相应环境的 `python` 执行同一脚本。先按原有取数/预取入口补齐数据，再冻结；要改变数据、参数或代码，应新建实验，不修改旧证据包。

成果目录：`webdata/replay_research/<实验ID>/`，包括 `manifest.json`、`evidence.sqlite`、四组计划、逐日 `states` 和 `report.json`。窗口太短时没有滚动结果，不用缩小样本门槛制造“最优方案”。

## 已知边界

分钟 OHLC 无法提供逐笔成交顺序或盘口排队；T+1、跳空与封死跌停可能令实际亏损超过预算。沿用的公司行为调整不是完整派息/送转现金账本。这些假设在四组保持一致，仍需要官方公司行为与盘口数据才能进一步提高仿真精度。
