# 相似评估与滚动验证：Phase 3—4

更新日期：2026-10-08。

## 已实现的内容

相似匹配、净盈利统计、滚动训练/校准/测试、不可变预测、实验报告和前瞻旁路评分。
不会修改买卖规则、仓位、换股或微信触发条件；工作台及微信展示留待Phase 5。
完整账户过滤/换股对照属于Phase 6，本阶段不能用信号平均收益冒充账户净值。

## 相似匹配的口径

硬边界：策略、入场模式、配置、特征版本、涨跌幅类别、分钟证据精度、成本和退出版本。
以上字段未知时不给个股概率，不自动把其他版本的数据补进来。

连续特征按市场、身份、日线、分时四类等权比较，同类因子数量不会增加整类权重。
尺度取训练期中位数及四分位距；不拿绝对股价作为距离特征。
情绪阶段、生命周期、龙头角色和确认时段不同会增加距离。
未知特征不填0；可比特征和类别太少时不建立精细近邻。

默认先取40个近邻，至少20例、8个交易日、12个权重有效样本。
这些是研究配置，不是已经被历史证明的通用胜率标准。
回退为：精细相似 → 同策略/模式/情绪阶段 → 同策略/模式 → 样本不足。
按距离与时间衰减加权，同一天的总权重有上限，并在当日题材之间分配。
有效样本数、交易日数和题材数分别返回，不能互相替代。

主成功定义为完整平仓净收益大于0，包含原冻结成本口径。
输出净盈利概率、净收益均值/中位数、平均盈利/亏损、盈亏比、盈利因子和收益分位。
概率区间采用交易日分块bootstrap，并增加小样本/全胜全负时的保守区间保护。
收益分位范围不是盈利概率置信区间；无亏损样本的盈亏比、盈利因子为null。
D+1/3/5、MFE、MAE只引用在评分时点各自已成熟的标签，并报告其有效数量。
匹配明细保留成功和失败案例、差异字段、权重及全部统计样本ID。

## 数据与性能

沿用原盘后任务，在案例增量阶段发布：

`WEB_DATA_DIR/signal_cases/matching_index.json`

索引默认最多5000个近期案例，体积上限16MiB；较老案例仍在DuckDB供离线验证。
实时读者使用现有文件版本缓存，不连接DuckDB、不重新取分钟数据。
盘后发布的是案例索引，不会每天自动选择新参数或重新训练模型。
本机合成1000例、20次评分的初步测量：训练约0.40秒，单次评分P95约148毫秒。
此数值只作为本机基线，不代表实际服务器或真实数据上的延迟保证。

SQLite增加`signal_case_forecasts`、`signal_case_matches`和`signal_similarity_models`。
首次预测、匹配明细和首次模型发布时间不可覆盖。重复验证会引用原预测而不是刷新它。
相似验证实验与原账户策略实验分开分类，不污染旧策略评估页面的下拉框。

## 初始化与运行

先按《信号案例库使用说明.md》补建Phase 0—2案例。代码部署不代表历史标签已经齐全。

1. 冻结滚动验证合同：

```bash
python scripts/strategy_experiment_ledger.py analog-freeze --label analog-v1
```

记录输出的`experiment_id`，后续作为`CONTRACT_ID`。
默认60日训练、20日校准、20日测试，训练/校准/测试之间各隔离5个交易日。
第一个完整窗口需要至少110个真实交易日；例如仅有8月至9月的数据，通常不够。
短区间可以在冻结前通过`--train-days`、`--calibration-days`、`--test-days`、`--gap-days`
指定探索窗口，但不会因此降低默认样本可靠度和发布要求。

2. 运行严格可获得时间验证：

```bash
python scripts/strategy_experiment_ledger.py analog-evaluate CONTRACT_ID --start 20260101 --end 20260924
```

3. 只有历史重建数据时，显式选择事件时间研究：

```bash
python scripts/strategy_experiment_ledger.py analog-evaluate CONTRACT_ID --start 20260101 --end 20260924 --research
```

`--research`使用历史事件结束时间模拟标签解锁，忽略后来补建的实际发布时间。
它不会改写数据库时间，所有报告和模型均标记研究口径，禁止因此获得生产资格。
严格模式同时检查标签结束和实际可获得时间，并要求PIT标记合格。

可用`--db`指定案例库、`--output`指定报告目录。
`--account default`附上现有账户的完整净值参考，但不会生成不存在的相似过滤账户对照。
范围不足、无真实日历或冻结后代码变化会明确报错，不能通过复用旧合同规避。

4. 查看单个案例的未校准研究统计：

```bash
python scripts/strategy_experiment_ledger.py analog-score CASE_ID --as-of 2026-10-08T10:00:00 --research
```

CASE_ID需存在于已发布索引；此命令不生成工作台买点，也不发通知。

## 报告与模型

默认输出目录：`WEB_DATA_DIR/signal_cases/validation/EXPERIMENT_ID/`。

- `report.json`：每折时间范围、参数选择、剔除数量、校准、测试指标、策略/情绪分组。
- `predictions.json`：冻结预测和匹配明细。
- `models.json`：全部冻结模型；每个模型另有`MODEL_ID.json`供单模型评分。

参数只在训练区间的内部时间切分中选择。独立校准区间拟合sigmoid校准器；
测试区间不参与参数选择或校准。跨边界尚未结束/发布的标签被剔除。
校准样本不足或只有一类结果时不拟合；负向校准关系标降级，不悄悄反转为新策略。
报告比较现有规则交易结果、简单分组概率基准和相似模型，并列出共同案例Brier分数、
校准误差、可靠性分箱、收益排序、预测覆盖、回退率及不同策略/情绪表现。

浏览已有报告不会触发重算：

- `GET /api/operations/experiments?kind=analog`
- `GET /api/operations/experiments/EXPERIMENT_ID/analog-validation`

## 前瞻记录和降级

历史时间切分正确仍不等于真实前瞻预测。
必须同时有测试前冻结的合同/模型，且预测确实在信号时点附近记录、早于结果结束，才能标记`prospective_oos`。
合同默认允许60秒计算延迟，迟到的回算不冒充当时预测。
模型的实际发布时间不倒填。历史重算标记`pit_time_split_replay`或`research_event_time`。

使用已实际发布的、非重建研究模型做前瞻旁路评分：

```bash
python scripts/strategy_experiment_ledger.py analog-score CASE_ID --as-of 2026-10-08T10:00:00 --model PATH_TO_MODEL.json --shadow
```

旁路允许记录尚未获准的参考预测，但始终不参与交易门禁。
正常参考评分不带`--shadow`，要求发布/验证时间早于查询时间、通过前瞻检验且未过期。
默认有效期30个自然日；过期不给概率，特征严重偏离训练近邻时退回分组基准。
基准也不足时明确返回null。

当前尚未连接实时确认回调与工作台。这些服务接口供Phase 5接入，
不能因为CLI支持旁路，就声称已有持续盘中预测。
