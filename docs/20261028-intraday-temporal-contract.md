# 盘中保护位、确认生命周期与调度修正

## 范围

依据 20261027 服务器调试日志修复时间及证据口径，不放宽开盘分层、龙头资格、VWAP、量能、追价、新鲜度或策略截止条件。此次不修改账户，不发送真实通知，不在线补造历史快照。

## 真实分钟结构与保护位

- eltdx 分时接口返回价格点，即便兼容字段 open/high/low/close 都有值，也不证明真实分钟高低点。
- 分时转换标记 `bar_kind=minute_price_point`，K 线转换标记 `minute_ohlcv`。旧 eltdx 缓存缺少类型且成交额为估算或来源不明确时，不再将其作为开盘结构证据。
- 独立 eltdx 采集器的分钟同步改用 `get_minute_ohlcv()`，复用现有 `get_kline(period="1min", count=800)`，按接口实际时间过滤请求交易日；取不到该日则为空，不重标日期、不用分时点伪造。
- 快照及分钟兜底均校验开盘 OHLC。分钟路径还要求五条开盘记录连续；不完整时等待或标记缺失。
- 快照保护位只使用开盘结构完成后的真实分钟低价、实际观察到的快照成交价，不再使用日内累计 `low_price`。
- 策略在内存保留已观察低点，独立运行时另存 Redis `realtime:protection:v2:<date>:<code>:<mode>:<boundary>`，有效期两日。热窗口退出及策略进程重启不会抹掉已记录的破位；日期、股票、模式和窗口隔离。
- 记录 `protection_window_start`、`protection_price`、`post_structure_low`、`first_break_at`、`session_low_used=false`。
- 快照判定版本标记升级为 `eltdx_snapshot_primary_v2_temporal_protection`，共享规则版本升级为 v13，旧日志不改写成新版本。
- 这些字段描述已观察证据，不宣称能恢复从未采集的历史轨迹。完整原始归档仍是精确回放的依据。Redis 丢失且历史分钟也不完整时，不能凭当前快照宣称复原了当天所有价格。

部署合并时保留远端已上线的可配置开盘窗口：高开加速默认一分钟、强势延续三分钟、弱转强五分钟。保护位边界跟随对应窗口，没有为追求速度直接使用未完成分钟。

## 信号时间

`EntryDecision` 及发布结果新增：

| 字段 | 含义 |
|---|---|
| trigger_at | 初次触发尝试，不保证确认条件全部通过 |
| formal_confirmed_at | 正式确认时间；无确认时为空 |
| invalidated_at | 破位或其他明确失效事件时间 |
| simulated_entry_at | 仅模拟成交成功时填入，不等于触发或确认 |
| rule_confirmed_at | 规则通过但被执行健康门禁阻断时保留的诊断时间 |

兼容字段 `confirm_time` 仅保留正式确认语义，取消及 quality_pending/quality_rejected 不再把尝试或破位时间塞进去。`initial_confirm_time` 是旧字段，按触发尝试解释，不应用来展示“曾正式确认”。

原来一字涨停开盘的提前分支，不再无条件写入 09:30 确认时间；尚未获得确认和可成交证据时保持观察。

逐股确认回调继续立即运行健康门禁、留档和通知入队，不等待整池完成或下一快照/下一分钟模拟成交。队列检查正式状态、正式时间、健康状态及否决原因，并保持原幂等及发送前过期检查。健康门禁否决时清空正式确认字段，保留规则诊断时间。

板块是否必需以冻结的确认策略配置为准。板块仅用于评分的模式，不会在健康门禁再次强制全量宽度必过；明确要求板块的策略和缺少该配置的旧格式仍执行原有检查。

## 资格与执行范围

- `acceleration_eligibility` 输出资格布尔值、解释、池类型及三个输入分数。
- 资格阈值不变：核心/板块龙头身份，或龙头质量至少 65，或主线至少 75 且地位至少 60。
- 连板龙头、趋势龙头、近期龙头标签本身不自动获得高开加速资格。
- `execution_sources` 保留龙头池、决策池的全部来源；`execution_pool` 表示最终执行来自哪个池；`execution_strategy_id` 表示实际策略。
- 维持同股去重、决策候选优先的执行模型，不擅自改成同一股票两套策略并行下单。
- 修复决策候选无 strategy_id 时继承 leader_pool 默认值的问题：使用 decision_pool 或候选自身的策略 ID，不沿用龙头观察行的执行限制。
- 循环日志新增来源池计数和实际执行策略计数，便于核对“两个池均被覆盖”和“实际采用哪套执行规则”。
- 发布结果新增 `execution_audit`：计划/有效执行数量、未进入有效执行集合的代码，以及逐股来源、最终执行池、策略、允许模式和高开加速资格；未执行代码需结合冻结配置检查停用状态及排除规则，不伪装成已判定。

## 会话与数据驱动

- 交易会话改为 09:30-11:30、13:00-15:00，保留结束时点最后报价的处理机会。
- 午休 `session_break=true`，下一开盘时间为同日 13:00，只更新会话心跳，不读取行情或运行买点判定。
- 下午恢复仍使用原连续快照和新鲜度检查，不能把上午最后一条与下午第一条拼成新确认。
- 修订号/PubSub 驱动、去抖合并更新及每分钟时间边界重判保留。时间边界重判用于截止、过期等条件，不是重新调用行情接口。
- 正式板块证据读取器无需候选间行情依赖时，只重判变化股票及相关板块/成分股影响的股票，并仅刷新所需缓存报价；保留旧候选样本相互依赖路径的全池重判。
- 未受影响股票复用结果但不作为新确认重新入队；Web 仍检查发布结果与原行情年龄。

## 验证与部署边界

回归覆盖：累计日低价不误取消、结构后真破位保留、窗口淘汰及重启恢复、分时点不得替代 OHLC、时间字段语义、资格阈值、同股来源及执行策略、午休和下午重建、确认未成交即入队、去重及健康阻断、可选板块评分与必需板块门禁隔离、增量影响范围。

发布后需重启独立采集器和策略进程，不能只重启 Web。现有 Linux `a-stock-market.target` 可统一管理；部署权限和是否启用真实通知沿用现有配置。

历史分时点归档不会自动变成真实 OHLC。对过去日期做修正版回放时，缺少真实结构应明确标记缺失；需要补真实分钟 K 线时使用独立补数任务，不允许策略或严格回放调用行情接口补取。不能据此宣称已重新算出 20261027 的真实漏买数量。

测试记录：扩大后的相关链路测试 398 项通过、7 项跳过。首轮全仓库测试尝试未完整结束，另定位到 `test_runtime_estimate_is_frozen_with_winners_losers` 的 AttributeError：analog_runtime 创建的 BacktestEngine 缺少 minute_evaluator。

后续已修复该错误：仅计算版本哈希时允许没有分钟评估器，从传入配置解析负反馈策略；已有冻结策略时优先使用冻结值，不初始化完整引擎或访问行情/日历。新增版本一致性、配置开关、冻结优先级及 OOS 策略解析回归，相似案例与负反馈相关测试共 130 项通过。未重新宣称全仓库测试通过。

部署前同步远端持久化行情、诊断日志、只读 API 和可配置开盘窗口后，相关回归共 645 项通过、7 项跳过；影子回放固定夹具自检通过。同步修正了测试夹具的 SQLite 连接释放、快照 mock 参数和 Windows 下不适用的 POSIX 权限断言，Linux 权限校验保留。以上是离线验证，不代表已完成真实盘中验收。
