# 历史重建缺失证据模式

在模拟交易页面填写起止日期，勾选“跳过缺证据候选，持仓缺证据仍停止”，再点“独立历史重建”。默认不勾选，默认账户的“补跑至结束日”不接受跳过模式。

- 当日未持有的候选缺少完整分钟、必要板块确认、同分钟量能等证据，跳过该股票当天的买入确认。其他股票继续，不用日线推测分时买点。
- 同一股票后续日期有完整证据时仍可参与；不会永久排除。
- 当日已有持仓缺少完整分钟时，在执行当日退出和净值计算前停止，不采用日线退出价格，不导入未完成的独立账户。
- 竞价缺失仅在当日策略执行契约明确要求竞价证据时阻断。允许分钟开盘确认的规则继续判断；真实但不达标的竞价仍按策略否决。
- 普通条件不满足、截止前未确认、涨停无法成交等不计为缺失证据。

跳过记录包含日期、股票代码、缺失证据、原因和策略 ID。覆盖率以进入分钟证据检查的“股票 × 日期”为单位去重：证据可用候选样本 / 全部已检查候选样本。它不是确认率或成交率，也不是全市场覆盖率。

只要发生跳过，页面和报告标注“数据不完整”。账户收益、胜率和回撤只反映剩余证据可用样本，不能当作完整策略业绩，也不能跨缺失比例不同的批次直接比较。

审计文件位于配置的 `OUTPUT_DIR/backtest_results`：`backtest_data_quality_<批次>.json` 和 `backtest_skipped_candidates_<批次>.csv`。完成后选择该独立历史账户仍能读取质量标记，重启服务不会消除该标记。持仓阻断时仅保存审计，不生成可导入的完整绩效结果。

上线需要更新后端和模板并重启服务。既有历史结果不会被自动重新计算或补加新的覆盖率；需用新模式启动新的独立历史重建。

## 全天停牌不是缺失数据

盘后取数和历史重建预取接入 Tushare `suspend_d`，缓存位于 `CACHE_DIR/stock/suspend_d/YYYYMMDD.json`，成功空结果也保留。接口失败、权限不足、日期不匹配或响应截断不写入成功缓存，不因“无行情”推定停牌。

只有当日 `S` 记录且 `suspend_timing` 为空、无复牌或日内停牌冲突时，才确认全天停牌：候选当天不买，持仓禁止卖出或换出，沿用最后可用估值并在审计中标记 `last_available_mark`。已确认全天停牌不降低候选证据覆盖率，不计入缺证据跳过。复牌后仍需真实分钟数据；日内临时停牌不适用全天豁免，目前残缺分钟仍保守阻断。

独立历史重建自动先补齐相关日期的停复牌证据。也可提前补取（不运行回放，不修改账户）：

```bash
python scripts/prefetch_suspensions.py --start 20260701 --end 20261009
```

强制重新查询加 `--force-refresh`。接口需要 Tushare `suspend_d` 权限；获取失败的日期会在命令输出中列出并返回非零退出码。计算引擎只读缓存，不在逐票判断时调用 Tushare。停牌审计另存为 `backtest_suspended_sessions_<批次>.csv`，接力账户检查点也保存停牌记录。

## 板块同步证据

历史回放的板块同步使用前一交易日因子表中的同板块样本，读取这些股票当日真实分钟行情，按确认时点统计相对昨收不弱的比例。它不是同花顺板块指数分时，也不是全部成分股覆盖率。当前至少需要两只有效样本，比例达到 55% 才通过；后续分钟不会倒灌到此前买点。

交易计划的板块字段支持原始列表、JSON 列表、历史 Python 列表字符串和分隔字符串。新计划统一导出规范板块名称，旧 CSV 在读取时正确解析，以完整板块名称匹配，不能用带括号引号的字符串或子串匹配。

“板块分时确认”缺失会列出板块名称、映射样本数量、确认时点有效观测数量及具体缺失股票。严格模式遇到候选缺失会停止；仅独立历史重建勾选跳过模式后，可以跳过该候选当天的买入，其他股票继续，报告仍标记数据不完整。
