# 板块证据缺失修复

## 已确认的问题

- Tushare 同花顺接口缓存包含 `700...` 分类指数，与普通 `8...` 交易板块不是同一口径。前一轮接纳这些分类参与确认的实现已经撤销。
- 名称解析曾按子串先到先得，可能先选到概念代理而不是准确行业。盘中确认只接受规范化后的精确名称匹配，并按候选日期排除尚未发布的板块。
- 初始盘前包仅保存候选/持仓的昨收行，没有保留全部板块成分股昨收。分钟存在但昨收缺失时，也无法算成分股涨跌幅。
- 原回放报告将尚未调用的板块检查当成缺失。开盘区间等条件先否决的股票，被错误列为 `sector_minutes`。
- 默认回放读取本地/Redis 缓存，未勾选补取不会自动下载历史成分股分钟。盘中成分股以批量快照采集，不需要每 3 秒下载全市场分钟。

## 代码修复

盘中确认仅使用本地同花顺元数据核验过的 `8...` 板块及其真实成分。`700...` 不进入名称解析、自动板块列表、成分读取或行情聚合；即使已有成分缓存或调用者传入成分覆盖表，也拒绝使用。未知 `8...` 代码同样不放行。名称只按精确名称与规范化罗马数字匹配，不按子串猜测替代板块。

旧盘前包及补件保持字节不变以便审计；实时及回放消费者仅使用其中绑定到 `8...` 代码的成分。新补件不再接纳 `700...`。保存的回放输入同时记录板块代码，旧报告若缺代码绑定，其成分不能作为确认依据，需要重新生成回放。缺少合格板块仍报告证据不足，不放宽门禁。

缺少列表或成分股时，证据准备器通过现有 Tushare 同花顺接口补取。空成分股缓存不会继续被当成有效缓存；指数列表不因可选字段为空而丢掉有效代码和名称。盘后流水线与盘前准备自动调用此过程。

新的初始盘前包保存相关成分股昨收。已有盘前包保持原文件不变，只能在 09:25 前新增带真实时间、完整性哈希及原包绑定的 `*.sectors*.json` 补件。补件只能填空缺板块名单和缺少的日线行，不替换已冻结候选、策略配置、已有成分股或已有价格。多个补件只追加，已存在文件不重写。09:25 后拒绝新增。

回放区分“尚未检查板块”“有数据但同步不足”“缺成分股分钟”“缺成分股昨收”“名称未解析”，展示缺失代码，不将未评估误报为缺数据。实时门禁、覆盖率和买点条件未放宽。

## 实际补齐与验证

## 服务器操作

代码部署后，在行情日 09:25 前执行：

```bash
python scripts/prepare_sector_evidence.py --market-date 20261014
```

该命令要求候选日正常盘后产物及原始盘前包已存在。过了截止时间不会补造新包或回填时间；缺少原始盘前包必须在下一交易日前正常准备。

历史回放勾选“补取缺失行情”，或运行：

```bash
python scripts/replay_intraday_day.py --date 20261013 \
  --codes 603230,600825,605577,601811 --until 10:30 --fetch-missing \
  --output outputs/publishing-evidence-replay.json
```

Linux 服务器若禁止直连行情节点，需要在允许采集的 Windows 节点补分钟，再同步缓存；不会绕过节点策略。运行中实时确认仍需要有效采集器租约、足够新鲜的报价和板块快照。缺真实证据继续拒绝确认。
