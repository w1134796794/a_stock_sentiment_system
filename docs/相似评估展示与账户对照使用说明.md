# Phase 5—6：相似评估展示与账户对照

## 已接入的功能

- 工作台候选详情新增“相似历史案例”：净盈利频率、区间、样本量/有效样本/交易日数、收益与下行尾部、盈亏筛选、分页、匹配差异、退出原因和费用。
- 案例图按成交价=100对齐，横轴是成交后的第1/3/5交易日；它是收盘价相对成交价的轨迹，不是可成交的分时路径，也不是扣完卖出费用的净值。
- 已确认信号由实时后台任务排队。页面/API只读SQLite中的冻结结果，不调用行情节点、不扫描DuckDB、不重新拟合历史。
- 微信沿用原有去重、主题上限和确认规则；评估未就绪或不足时仍发送原有消息，不等待模型，不在评估完成后补发第二条买入提醒。
- 买入及自动退出/换股成交绑定forecast_id。历史成交并列显示实际盈亏与估计；计算晚于下单的评估标成“下单时未就绪·补充参考”，不会冒充当时已知信息。
- 持仓监控旁路记录当前持仓状态，包含持有天数、浮盈亏、结构距离、市场/板块观测时间，缺少时间或数据时保留缺失并阻止匹配。不会复用原买入概率。
- 独立实验对照三个账户：原资金/强弱规则、相似统计过滤、过滤加换股；最多3只，T+1，等待下一观测成交，计入滑点、佣金和印花税。

现有默认模拟账户、手工成交、生产买卖规则均未改变。没有通过真实前瞻验证的结果仅作历史频率参考，不保证胜率或收益。

## 展示的前提

1. 先按 Phase 0—4 的说明补齐案例/成熟标签，并发布 `webdata/signal_cases/matching_index.json`。实际位置由WEB_DATA_DIR决定。
2. 正常启动 `python run_web.py --port 8011`。实时确认后台在确认事件之后生成评估任务。重启后待处理任务可恢复，SQLite租约避免多个Web进程同时计算；计算失败不阻塞原通知。
3. 打开工作台候选详情。查询可以按候选日或行情日找到该股票对应的已冻结确认评估。没有确认事件、同版本样本不足、PIT时间不合格都会明确显示未就绪/不足。
4. 如要使用已批准的校准模型，可设置 `ANALOG_MODEL_FILE` 为 Phase 4 输出的单模型JSON路径，再正常重启服务。未来发布、已过期、研究重建、未通过前瞻发布条件的模型不会被当作已校准模型使用；默认仍是未校准历史参考。

冻结估计不会因刷新页面、换了一批历史数据或更改参数而覆盖。旧成交没有绑定评估的显示“--”，不自动事后填上胜率。

## 只读接口

- `/api/signals/{signal_id}/similar-cases?offset=0&limit=10`
- `/api/v1/workbench/analog-analysis?date=20260901&code=600001&offset=0&limit=10`，沿用工作台的ok/data响应格式。

所有接口沿用现有登录与菜单权限。实验报告在“策略评估 → 评估类型 → 相似案例与账户对照”中查看，包括三账户净值、回撤、费用、换手和资金利用率；展开“信号行动比较”可查看保持、现金买入、换股、暂不行动的资格及否决原因。运行实验通过离线脚本，不在GET请求里计算。

## 冻结账户实验

```powershell
python scripts/analog_account_experiment.py freeze --label analog-shadow
python scripts/analog_account_experiment.py replay <contract_id> --tape <events.json> --holding-states <mature_states.json> --research --output outputs/analog-accounts.json
```

可通过全局 `--ledger <path>` 使用独立SQLite；不指定则只向现有审计库写入独立实验与净值，不修改portfolio_positions/portfolio_trades。配置使用全局 `--comparison-config <json>`，冻结和回放必须一致，代码改变后也必须重新冻结。

账户键是 `analog:<experiment_id>:<variant>`，各账户独立从100万元开始。不会导入、重置或覆盖当前默认账户及手工交易。相同合同+事件+历史状态输入只产生一个实验结果；更改数据产生新版本。

### 事件文件约定

`events.json` 包含完整真实 `trading_dates` 与按时间排序的 `events`。日期缺口不能用“工作日推算”代替。每个交易日最后一条事件必须是唯一session_close。每个事件提供该时点候选/持仓所需的报价，格式例如：

```json
{
  "trading_dates": ["20260901"],
  "events": [
    {
      "at": "2026-09-01T09:40:00",
      "quotes": {
        "600001": {"last_price": 10, "volume": 1000, "observed_at": "2026-09-01T09:40:00", "limit_pct": 10, "limit_up_locked": false, "limit_down_locked": false}
      },
      "signals": [],
      "exits": [],
      "market": {"market_score": 60, "observed_at": "2026-09-01T09:40:00"},
      "sectors": {"600001": {"breadth": 0.6, "observed_at": "2026-09-01T09:40:00"}}
    }
  ]
}
```

这是字段示例，不是可直接跑完一天的完整行情文件。signal需提供 signal_id/code/confirm_at/strength/theme/strategy_id/config_version/structural_stop，以及冻结forecast_id和评估中的remaining_horizon。未给评估的候选只参与原规则账户。`exits`是原规则在该时点已经产生的卖出信号代码，不能从日后成交倒推出一个更早的“完美卖点”。

每个信号/退出指令在后续观测才执行。只有分钟点的输入是分钟观测估计，不能宣称具有真实逐笔/盘口成交精度；没有盘口时不要伪造bid_price/ask_price。必须保留实际可得时间，零成交量、停牌、涨跌停锁定不能填成正常可成交。缺失/过期执行或估值报价会回滚并停在该日，不跳过后继续画净值。

本阶段没有把旧的日线回测成交自动转成可信事件文件：需要有逐时点报价、原规则退出事件与冻结预测证据。历史分钟证据缺失时不能补成看起来连续的账户结果。

## 持仓状态样本与固定未来区间

```powershell
python scripts/analog_account_experiment.py export-states --start 2026-09-01 --end 2026-09-30 --output outputs/holding-states.json
python scripts/analog_account_experiment.py mature-states --tape <states-and-close-quotes.json> --output outputs/mature-states.json
```

export-states读取旁路holding_state事件。成熟文件输入可以把导出的states与未来events收盘报价合并，补充真实published_at；也可以为每条state显式提供horizon_end/exit_quote/available_at。脚本用真实交易日历检查第N个交易日，参考价必须是冻结状态的价格。缺少未来收盘/可成交退出证据则标签保持空。

新票使用相似案例中第N交易日收盘收益，扣除对应买卖成本；持仓使用当前冻结时点至第N交易日的剩余收益，扣除未来卖出成本。两者必须同区间、同成本版本。持仓匹配还检查策略版本、涨停制度、持有天数、浮盈亏、结构、市场、板块、时段，剔除尚未成熟/未来才可得的标签，并按股票/交易日去重。

换股要求新票收益区间下界，仍高于持仓收益区间上界加额外换股成本缓冲和冻结优势门槛；同时满足样本、尾部风险、可卖资金、主题集中度和T+1。同主题挤满或持仓状态样本不足时保留持仓，不拿入场预测代替剩余收益。

没有持仓状态历史时，现金买入过滤仍可以评估，换股分支明确不通过。回放现场才计算的持仓估计保留真实生成时间，不能冒充在过去已发布；历史对照必须显式使用research。新收集状态要经过未来观察期并积累足够独立交易日后，才能成为有效匹配样本。

## 验证边界

代码与合成数据测试验证的是时序、账户隔离、幂等、费用和显示契约，不是策略有盈利优势。当前没有据此发布生产过滤/换股开关，也未发送测试微信消息。仍需真实事件文件的历史研究及前瞻独立账户对照，才能判断相似评估是否提升完整账户表现。
